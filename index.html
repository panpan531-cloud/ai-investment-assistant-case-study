AI 投研助手

把分散的市场信息，转化为一条可追溯、可验证、可复盘的研究决策链。

我没有把产品定义成“自动给答案的荐股工具”，而是把 AI 放进研究流程中：先建立可靠证据，再辅助形成判断，最后保留决策依据与后续验证。

01 / PROBLEM

问题不在于信息少，
而在于判断没有沉淀

普通人做投资研究时，真正的阻力不是找不到内容，而是资讯、宏观、财务、行情散落在不同入口；当下形成的看法缺少结构化证据；过一段时间又很难说清，当时为什么做出那个判断。

01

信息零散

资讯、宏观、财报、研报和市场行情分散在多个入口，研究精力被搜索、筛选与搬运反复消耗。

02

判断临时

从信息直接跳到结论，缺少结构化的证据链、反方观点和可验证条件，判断质量高度依赖当时状态。

03

复盘缺失

标的进入关注范围后，理由、来源、状态变化和最终结果没有被连续记录，经验无法沉淀为方法。

02 / STRATEGY

我的产品判断

AI 的价值不是替用户承担决策责任，而是降低信息处理成本、固定分析结构、主动暴露风险，并让每一次判断都能回到原始证据。

WHY · 为什么做

个人投研最缺的不是更多资讯，而是把资讯变成可解释判断的稳定过程。

HOW · 怎么解决

用数据质量门禁打底，用分层 Agent 处理不同复杂度任务，用状态化股票池闭合研究与复盘。

WHAT · 产品目标

让用户从“今天发生了什么”，一路走到“我为什么关注、什么条件会推翻判断、后来结果如何”。

03 / PRODUCT SYSTEM

一条完整决策链，
而不是功能堆叠

每个模块都承接上一步的证据与判断，也为下一步提供明确输入。这样，信息浏览、个股研究、筛选和跟踪不再是相互割裂的动作。

状态管理

股票池不是收藏夹

每个标的都携带进入理由、证据来源和历史状态，以“观察 → 可交易 → 持仓 → 归档”推动模拟跟踪与复盘。

  • 观察
  • 可交易
  • 持仓
  • 归档
闭环原则

所有结论都必须能返回证据，所有状态变化都必须保留原因。

这是我为产品设定的核心工程约束。它把“看过很多内容”变成“形成过哪些判断”，也为后续评测与复盘提供统一对象。

04 / DATA TRUST

先让数据可信，
再让模型聪明

开发中最容易被忽视的风险是：接口正常返回，不代表数据有效；代码顺利运行，也不代表计算逻辑正确。错误数据一旦进入模型，表达越流畅，误导反而越强。

01

数据源接入前门禁

分别检查可用性、时效性、准确性。接口是否能调通只是第一步，还要抽样核对日期、单位、缺失值和交叉来源。

02

进入 LLM 前门禁

对清洗、映射和计算过程做独立校验，重点防止历史分位方向颠倒、单位换算错误和字段语义错配。

数据类别主来源备用与补充
行情 / 估值 / 市场宽度Tushare 基础、日线、每日指标、指数日线新浪财经、efinance、mootdx、Baostock
财务 / 分红 / 两融Tushare 利润表、资产负债表、现金流、分红、融资融券新浪财经、Baostock

数据策略：付费数据提供稳定基线，多源数据做互补；每一类关键数据至少保留一条备用路径，切换时记录来源与更新时间。

05 / ASK AGENT

问势 Agent：
从问题到证据

问势 Agent 是整个产品的开放式多轮研究入口。它不预设用户一定从某个功能开始，而是先理解问题、识别标的和研究意图，再选择分析框架与工具，把取数、计算、搜索和解释组织成一次可追溯的研究过程。

DESIGN PRINCIPLE

模型负责规划与解释，
工具负责取数与确定性计算

这样既保留自然语言交互的灵活性，又避免让模型凭记忆回答实时行情、技术指标和历史结果。

TOOLTool 解决“能做什么”
获取数据、查询资料、执行计算
SKILLSkill 解决“按什么方法做”
规定证据、判断规则与输出重点

四种分析框架

默认使用通用分析；用户也可以显式选择研究视角。框架可以组合，但最多同时启用三个，避免上下文堆积、规则冲突和结论失去主次。

01 · GENERAL

通用分析

综合趋势、量价、筹码、风险与验证条件，适合尚未明确研究视角的开放问题。

02 · TREND

趋势研判

看价格与量能，回答当前怎么走、趋势是否成立，以及什么条件下原判断会失效。

03 · CATALYST

题材催化

看政策、事件、公告与板块反馈，判断为什么现在变化、催化是否真实并可能持续。

04 · GROWTH

成长研究

看收入利润、ROE、现金流、行业空间与估值，判断增长质量和预期是否已经透支。

18 个工具，按职责分成五类

工具以结构化 Schema 注册。模型只负责选择工具与生成参数，真正的权限检查、调用和结果归一化都在后端执行层完成。

06 / AGENT STRATEGY

三种模式，按任务难度分配成本

我没有把多 Agent 当成默认答案。研究任务的复杂度不同，日常摘要、重点个股和高争议问题需要的推理深度也不同，产品需要在速度、成本和可靠性之间主动路由。

FAST · 高频默认

快速模式

适合每日简报、批量初筛与低争议任务

  • Structured Prompt
  • →
  • Answer
  • 单次结构化调用，速度快、Token 成本低
  • 通过证据约束和固定字段提升日常稳定性
  • 主要风险是虚构引用或前后矛盾，需要数据门禁兜底
DEEP · 重点研究

深度模式

适合重点个股、复杂公司与结论复核

  • Researcher
  • Writer
  • Critic
  • Researcher 先整理证据与缺口
  • Writer 形成结构化报告并保留版本
  • Critic 使用另一模型提供方独立审查，避免同源自证
DEBATE · 高争议任务

辩论模式

适合分歧明显、信息不完备的研究问题

  • Bull
  • Bear
  • Risk
  • Synth
  • Bull 与 Bear 分别建立正反证据链
  • Risk 专门寻找共同遗漏与尾部风险
  • Synth 不强行求同，而是呈现分歧、假设与触发条件
关键取舍

更重的链路不等于更好的答案。优化后的快速模式已经能覆盖大部分日常需求；只有当研究价值和不确定性足够高时，才升级到深度或辩论模式，把有限成本花在真正需要推理的地方。

训练记忆冒充实时事实

部分模型会把过期信息写成当前状态，因此所有时效性陈述都必须回链到冻结快照。

跨模型一致不等于独立证据

不同模型对估值区间与情景概率常出现趋同，本质上可能来自相近语料与叙事惯性。

擅长外推，不擅长主动反证

模型容易沿初始观点继续推演，却不会自动回看输入中的冲突信息，所以需要 Critic 与 Risk 角色。

MODEL ORCHESTRATION

双模型协作，
把规划、分析与复核分开

问势 Agent 不让单一模型包办全过程，而是按能力拆分职责：先规划任务和工具，再基于证据完成分析，最后回到独立视角检查风险与遗漏。

ANALYSIS & WRITINGDeepSeek基于工具返回的证据，负责主要分析、逻辑组织与结构化写作
PLANNING & REVIEWGLM负责 Agent 的任务规划与工具编排，并承担结果复核、风险补充与遗漏检查

08 / OUTCOME & LEARNINGS

阶段结果与复盘

当前成果定位为验证版本：我完成了核心流程、数据策略、Agent 路由和评测框架的闭环验证，但不把尚未发生的用户增长或投资收益包装成项目结果。

01

流程被统一

日报、研究、筛选、股票池与复盘被串成同一条决策链，模块之间有明确输入输出。

02

证据可追溯

事实、分析、风险与验证条件分层保存，结论可以回到对应数据和资料来源。

03

成本可路由

快速、深度、辩论三种模式按任务难度分配，避免所有问题都调用最重链路。

04

模型可比较

建立同一快照、统一量表和多轮波动评估，让模型选型从主观体验变成可重复实验。

这个项目让我重新理解了 AI 产品的价值：不是“让模型多想一步”，而是“让系统少错一步”。

  • 数据质量优先于模型能力。 无效数据进入再强的模型，也只会得到更有说服力的错误。
  • 复杂编排必须有使用场景。 多 Agent 适合高价值、高不确定性任务；高频任务更需要稳定、快速与低成本。
  • 一致答案不代表正确。 真正可靠的系统要主动寻找反证、记录分歧，并说明结论失效的条件。
  • 下一阶段验证重点。 用真实任务记录研究耗时、引用错误率、状态复盘完成率，再决定哪些模块值得产品化投入。

PROJECT SUMMARY

项目总结

我做的是一款面向个人投资研究者的 AI 投研助手。它解决的不是“信息不够”，而是信息分散、判断临时和无法复盘。我把产品设计成一条从资讯日报、宏观情绪、个股研究，到规则筛选、股票池和模拟跟踪的完整决策链。其中，问势 Agent 作为开放研究入口，用 Skill 固定分析方法，用 18 个工具完成取数、计算、搜索和历史验证，再根据任务难度路由快速、深度和辩论三种执行模式。在模型协作上，由 GLM 负责 Agent 的任务规划、工具编排和结果复核，DeepSeek 基于证据承担主要分析与结构化写作，再由 GLM 补充风险和检查遗漏。这个项目最核心的取舍，是不让 AI 替用户做投资决定，而是让每一次判断都有证据、能被质疑，也能在之后被复盘。
